# Issues

Open bugs and improvements only, one line each, in English. Delete an item's line when it is fixed.

## Bugs

- Auth: `responseUser()` (`Auth.php`) unsets `password`, `auth_type`, `level`, `experience` on the shared `$this->session->user` object, so code after it in the same request reads null; nothing reads them today, build a copy instead.
- VPS: the Next.js process grows to 1 GB and PM2 restarts it every 15–30 minutes (`max_memory_restart: '1G'`, 141 restarts by 2026-10-17) on a 1-CPU, 1.5 GB VPS without swap; find the leak (heap snapshot under load) or lower the limit and add swap.

- Migrations: rolling back all migrations on MySQL (`tests/database` run against the MySQL `tests` group) stops at `AddLocationDedupSlugsAndLegacyIds::down()`: `Cannot drop index 'idx_locality_category': needed in a foreign key constraint` (MySQL dropped the implicit foreign key index when the composite one covered it); a committed migration, so fix it with a new one or accept that it does not roll back. On SQLite the suite passes.

## Improvements

- Places: no rate limit on `POST /places`, `PATCH /places/:id` and the photo uploads, so one signed-in account can flood the site with places, edits and files; add a per-user limit (an IP one shares a bucket behind a proxy while `App::$proxyIPs` is empty, and `ThrottleFilter` keys by IP only, one bucket for all its routes).
- Places: an edit cannot clear a description (`Places::update()` reads an empty `content` as "not given" and keeps the old text), yet the form saves without an error; tell the user or allow clearing.
- Places: a description may embed images from any site (`![](https://…)` in markdown), which loads a third-party URL for every visitor; allow images only from our and Wikimedia hosts, or render them as links.
- Places: `POST /places` and `PATCH /places/:id` have no endpoint tests (auth, validation answers, the transaction); only `PlaceInput` is covered by unit tests.
- Places: `GET /places?search=` with 1–3 characters takes the 100 most recently updated matches (`PlacesContent::SHORT_TERM_LIMIT`) before the other filters (category, bounds, distance sort), so a filtered short search may miss places; move the short search into the list query.
- Push: quiet hours use only the time zone of the user's most recently updated device; a user with devices in different time zones may get a push at night on another one.
- Achievements: without the hourly `achievements:evaluate`, a reputation achievement (reputation grows from other people's ratings) arrives only with the user's next own action; and every place / photo / rating / comment now also evaluates the experience, level, reputation, active days and streak metrics (`AchievementsLibrary::ALWAYS_METRICS`), `login_streak` reading all the user's activity days. Watch the cost; if it grows, cache the streak or run `achievements:evaluate` for the users active in the last hour.
- Push: delivery was checked against a mock push service and the real FCM endpoint format, not yet on a real device; check Chrome / Firefox / Android / an iOS Home Screen app after the first deploy (`/users/settings` → Send a test).
- Home page (EN): many place and collection titles stay in Russian because they have no English text; prefer items with an English title in "Where to go" and the collections on `/en`, or transliterate.
- Places: the temporary 301 of full page loads of 2+ category lists to the first category (`proxy.ts`, `config/nginx.conf`, 1.18.3) also drops the second category and the other filters for people on a reload or a shared link; remove it once the combination scraper is gone (API CP back to normal for a few weeks), or keep combinations only for signed-in users.
- Server CI: no static analysis; add PHPStan (level 0–1, `codeigniter/phpstan-codeigniter`, a baseline) to `api-checks`.
- Email: only a synchronous rejection of the recipient at RCPT TO (5.1.1/2/3/6/10) marks `users.email_bounced_at` (cleared on the user's next sign-in); bounce and spam-complaint emails that arrive later in the `smtp.mail` mailbox are not processed. Read them (IMAP) or move to a provider with bounce webhooks.
- Email: the settings hint "at most once every 5 hours" (`email-notifications-hint`) duplicates `Config\Notifications::$activityEmailIntervalHours`; send the interval from the API or keep them in sync by hand.
- SEO: the Open Graph image `client/public/images/pages/main.jpg` is 1768×1538, social networks crop it; add a 1200×630 image and an explicit `twitter:image`.
- Places: the new filter primitives (`Chip`, `ScrollRail`, `Switch`, `FieldTrigger`, `OptionList`, the form `BottomSheet`) live in `client/components/ui`; move them to `simple-react-ui-kit` once they settle.
- Places: "Near me" is the distance sort over all places, without a radius; a filter by distance (e.g. 300 km) needs a server parameter.
- Mailings: the audience is not compared with what the hosting limits can send before the letters expire (`digestDayLimit` × `newsExpireAfterDays`, shared with the digests), so the tail of a big audience silently ends `expired`; return the estimated days from `GET /mailings/audience` and warn in the send confirmation.
- Mailings: `MailingContent::inline` applies bold per part after splitting off the links, so `**[link](/x)**` keeps the asterisks.
- Seasons: a picture replaced or a season deleted leaves the old file on disk when the DB write fails in between; a cleanup command for `uploads/seasons` would catch it.
- Admin: `useQueryFilters` rebuilds `setFilters` on every route change, so the achievements search can cancel a pending debounced change typed while the URL updates; keep the callback in a ref.
- Game: `loadGamePage` asks for the leaders and the places even with no current season, and `loadSeasonPage` for the leaders of an upcoming one, which are not shown.
- Home: the newcomer's step "take a photo on the spot" (`HomeFirstSteps`) links to `/game/help`, nothing there starts the action.
- Tests: no tests for `AchievementForm`, `useQueryFilters`, `useAdminAttention`, `AdminLayout` marks, `getAdminServerSideProps`, or the page loaders `loadGamePage` / `loadSeasonPage` / `loadQuestPage`.
