# Идея: наполнение «таинственными местами России» через автономного SEO-агента

Статус: идея, не начато (2026-10-09).

## Суть

В AI-фабрике есть автономный SEO-агент с доступом к сайту от имени пользователя, Яндекс Вебмастеру,
Яндекс Метрике и Google Search Console. Хотим, чтобы он сам заводил новые места тематики
«аномалии, мистика, легенды», писал по ним статьи и прикреплял хотя бы одну фотографию.

Схема: с внешнего источника берутся только **название и координаты** (затравка), дальше агент
независимо ищет факты в открытых источниках, пишет текст с нуля и берёт фото с Wikimedia Commons.
Карточка места в итоге происходит из открытых данных, а не из сайта-затравки.

## Что уже есть в проекте

- Сборщик кандидатов из OSM и Wikidata (`OsmCollector`, конфиг `server/app/Config/OsmCandidates.php`,
  `/osm-candidates`), Wikidata уже отдаёт фото (P18) и статьи Википедии.
- Внешние фото (`places_external_photos`, API `external-photos`): фото с Commons прикреплять только
  так, с автором и лицензией — загрузка файла как своего фото нарушит CC BY-SA.
- Отдельной категории «мистика/аномалия» нет (ближайшие: `archeology`, `abandoned`, `cave`, `death`);
  если выделять такие места — новая категория или тег.

## Юридические правила для агента

Отдельные факты (название, координаты) авторским правом не охраняются; риск есть только при массовой
выгрузке существенной части чужой базы (право изготовителя БД, ГК РФ ст. 1333–1336). Чем меньше
берём и чем больше добавляем своего, тем ниже риск.

1. Брать с сайта-источника **только название и координаты**. Описания не брать даже как черновик.
2. Хранить у места ссылку на источник затравки (чтобы при претензии указать и при необходимости убрать).
3. Для Wikimapia и Википедии указывать источник на странице места (CC BY-SA).
4. Фото только через `external-photos` с автором и лицензией; подходят CC BY, CC BY-SA, CC0, Public Domain.
5. Текст писать своими словами по фактам из Википедии/Wikidata, с явной пометкой «легенда/гипотеза»
   и ссылкой на источник.

## Алгоритм агента

1. Получить список затравок: GPX из RAZA (после разрешения), категории Wikimapia, `/osm-candidates`
   после расширения конфига.
2. По каждой затравке: поиск в Wikidata (по названию + координатам в радиусе ~1–3 км), затем статья
   в Википедии, затем фото: P18 → категория Commons у статьи → геопоиск Commons по радиусу.
3. **Заводить только те места, где нашлась хотя бы одна свободная фотография.** У «народных»
   аномальных зон фото на Commons часто нет, такие пропускать.
4. Проверить дубликаты (логика уже есть в кандидатах).
5. Создать место через API от имени отдельного технического аккаунта (массовый импорт от обычного
   пользователя будет виден в ленте активности и в XP).
6. Прикрепить фото через `external-photos`, записать источник затравки.

## Ожидания и риски

- Фото с Commons получат, по оценке, меньше половины затравок. Лучше 50 хорошо описанных мест с фото,
  чем 500 без.
- Для Яндекса и Google тексты по легендам легко становятся «тонким контентом»: следить за объёмом и
  уникальностью, не плодить шаблонные страницы.

## Первый шаг, когда вернёмся

Взять GPX из RAZA и категории Wikimapia как список затравок, прогнать через Wikidata и геопоиск
Commons по координатам и посмотреть, какая доля получит фото. По результату станет ясно, сколько мест
реально выйдет и стоит ли вводить отдельную категорию.

Технические шаги на стороне проекта:

- расширить `$types` и `$wikidataTypes` в `server/app/Config/OsmCandidates.php` «мистическими» типами;
- описать в `server/API.md` сценарий для агента (поиск кандидата → создание места → привязка фото);
- решить, нужна ли категория/тег «аномалия, легенда».
