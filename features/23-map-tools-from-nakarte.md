# 23. Map Tools from nakarte.me — панорамы, профиль высот и другие инструменты карты

> Статус: идеи собраны в обсуждении 2026-10-07, реализация не начата.
> Контекст: в 1.12.0 на `/maps` добавлены рулетка и измерение площади (`components/map/ruler`, `components/map/area-measure`).

## Источник

[nakarte.me](https://nakarte.me), исходники: [wladich/nakarte](https://github.com/wladich/nakarte), лицензия **MIT**. Код можно переносить с указанием автора.

nakarte написан на «голом» Leaflet и Knockout, у нас react-leaflet. Модули придётся переписать как React-компоненты по образцу `Ruler.tsx`, но логика переносится почти напрямую. Все модули лежат в `src/lib/`.

## 1. Панорамы: Google Street View и Mapillary

Модуль nakarte: `leaflet.control.panoramas`, источники в `lib/`: `google`, `mapillary`, `mapycz`, `wikimedia`.

Как это работает у них:
1. Кнопка включает слой покрытия (синие линии там, где есть панорамы).
2. По клику на карту ищется ближайшая панорама в радиусе.
3. Панорама открывается в панели под картой или сбоку.
4. На карте маркер с направлением взгляда, синхронизирован с панорамой: при движении по улицам маркер едет, при повороте камеры поворачивается.

### Google Street View

- Google Maps JS API, загрузка скрипта по требованию (`src/lib/googleMapsApi`).
- Поиск: `StreetViewService.getPanorama({ location, radius, preference: NEAREST })`.
- Просмотр: `google.maps.StreetViewPanorama`, события `position_changed`, `pov_changed`, `closeclick`.
- Ограничения:
  - нужен ключ Google Maps API с биллинг-аккаунтом: есть бесплатная месячная квота, дальше платно; поставить лимит в консоли;
  - слой покрытия nakarte берёт с недокументированного URL `maps.googleapis.com/maps/vt?...svv`, это серая зона по ToS. Официально покрытие есть только как `StreetViewCoverageLayer` внутри Google-карты. Можно обойтись без слоя: клик в любое место, поиск ближайшей панорамы.

### Mapillary

- Открытый и бесплатный, нужен только токен.
- Официальный векторный слой покрытия и свой просмотрщик `mapillary-js`.
- В России покрытие часто свежее, чем у Google. Возможно, стоит сделать первым источником.

### UI

Одна кнопка «Панорамы» на карте и выбор источника. Wikimedia Commons можно сделать третьим источником той же панели (см. раздел 2).

## 2. Доработка слоя Wikimedia Commons

Слой уже есть: `components/map/wikimedia-commons/`, API в `api/apiWikimediaCommons.ts` (`generator=geosearch` по границам видимой области, `ggslimit=50`). В 1.13.0 добавлены листание всех фото области в просмотрщике и панель состояния слоёв (`components/map/layers-status/`): число объектов, спиннер при загрузке, `50+` при упоре в лимит.

Проблемы:

1. **На мелком зуме слой пустой.** Если область больше примерно 10 км, API отвечает `200` с телом `{"error":{"code":"toobig","info":"Bounding box is too big"}}` (проверено 2026-10-07). Запрос не считается ошибкой, и панель состояния показывает «—», как будто фото в области нет.
   - Быстрое исправление: не делать запрос ниже порогового зума и показывать в панели подсказку «Приблизьте карту, чтобы увидеть фото».
2. **Лимит в 50 точек.** В плотных местах, например в центре Москвы, фото в десятки раз больше, и мы показываем случайные 50 (панель состояния лишь помечает это как `50+`).
   - nakarte не запрашивает точки: она рисует покрытие из своих бинарных тайлов (`lib/wikimedia/coverage-layer.js`, `Uint16Array` координат, отрисовка на canvas), поэтому все фото видны точками на любом зуме. Тайлы лежат на их сервере, подключаться к ним напрямую некорректно.
   - Наш вариант: разбить область на несколько запросов или собирать точки в кластеры.

## 3. Профиль высот для рулетки

Модули nakarte: `leaflet.control.elevation-profile`, `elevations`.

- Для линии рулетки показывать график высот, набор и сброс высоты, минимум и максимум.
- У nakarte свой DEM-сервер. Нам нужен свой источник: Open-Meteo Elevation API или Mapbox Terrain-RGB (токен Mapbox уже есть).

## 6. Слой Wikimapia: как устроен у nakarte

Модуль: `src/lib/leaflet.layer.wikimapia/` (`index.js`, `wikimapia-loader.js`, `wm-utils.js`). Слой работает в обход официального API: он берёт внутренние тайлы, которые использует сам сайт wikimapia.org.

### Источник данных

- Запросы идут на `https://proxy.nakarte.me/wikimapia/z1/itiles/032/203/1.xy` (`config.wikimapiaTilesBaseUrl`), то есть через собственный прокси nakarte. Прямой доступ к wikimapia.org из браузера не даёт CORS.
- Номер тайла записан в виде quadkey: тайл `(x, y, z)` превращается в строку цифр 0–3, и она режется по три цифры на папки (`getTileId` и `makeTilePath`).
- Сам тайл — текст во внутреннем формате Wikimapia: строки, поля разделены `|`. На каждый объект приходится id, границы, названия на нескольких языках (через разделитель `\x1f`, первый символ — код языка) и полигон.
- Полигоны закодированы так же, как Google Encoded Polyline (`decodePolygon`), с точностью 1e-6.

### Загрузка

- `TiledDataLoader` с кэшем. Тайлы данных есть только для зумов 1–15. На большем зуме берётся родительский тайл и масштабируется (`calcAdjustment`).
- Тайлы крупные, 1024 px, поэтому запросов мало.
- Полигоны упрощаются под текущий масштаб (`simplifyPolygon`, `L.LineUtil.simplify`) и переводятся в пиксели тайла.

### Отрисовка

- Слой построен на `L.GridLayer`. Каждый тайл — `<canvas>`, на нём все полигоны рисуются тонкой жёлтой линией `#CFA600`.
- DOM-элементов и маркеров нет, поэтому слой быстрый даже при тысячах объектов.

### Взаимодействие

- При движении мыши слой ищет полигон под курсором простой проверкой «точка внутри многоугольника» (`isPointInPolygon`) по данным уже загруженных тайлов. Найденный объект подсвечивается настоящим `L.polygon`, рядом показывается tooltip с названием.
- По клику открывается всплывающее окно с карточкой объекта на wikimapia.org.

### Можно ли сделать так у нас

- Если повторять в лоб, понадобится свой прокси к внутреннему, недокументированному формату. Он может сломаться в любой момент и, скорее всего, нарушает их условия использования. Не рекомендуется.
- Легальный путь — официальный API (`api.wikimapia.org`, `function=box`). Он отдаёт объекты в границах области в JSON, нужен ключ, есть лимиты на частоту запросов. Данные Wikimapia под лицензией CC BY-SA, значит обязательна атрибуция. Запросы лучше делать через наш сервер с кэшированием, так же как сборщик `OsmCollector` ходит в Overpass.
- Сама идея отрисовки полигонов на canvas по тайлам, с подсветкой при наведении, пригодится независимо от источника. Например, для контуров объектов из OSM в слое «Места для исследования» (`components/map/osm-candidates/`).
- Wikimapia почти не развивается, а данные во многом устарели. Для заброшек и подобных мест OSM с Overpass обычно полезнее.
