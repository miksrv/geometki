# 20. Location SEO Pages — посадочные страницы по локациям и категориям

> Статус: всё построено (сервер и клиент, 2026-10-09/10), запуск поэтапный за флагами. Страницы категорий включаются в 1.14.x (`NEXT_PUBLIC_LANDING_CATEGORIES='true'` в `.github/workflows/ui-deploy.yml`); локации и комбинации пока выключены. Документ — правила, на которые ссылается код, и оставшиеся шаги запуска. Что делает каждый флаг — `client/utils/placesLanding.ts` (`getLandingFlags`, `buildPlacesHref`).

Цель: у каждой пары «локация / категория» свой URL, title, H1, описание и перелинковка вместо фильтра `/places?region=2&category=cave`. Карточки мест (`/places/{id}-{slug}`) не затрагиваются.

---

## Предусловия

**Дубли локаций от геокодера.** Сопоставление по точному названию плодило дубли (Оренбург id 1 и 225, «Республика Башкортостан» и «Башкортостан»…). Теперь локация опознаётся по OSM-объекту (`osm_type`/`osm_id`, ISO-коды), прежние имена — в `location_aliases` (`App\Libraries\Geocoder`). Дубли сливает и слаги раздаёт одноразовая команда `php spark locations:rebuild`; всё в одной миграции `2026-10-09-000001_AddLocationDedupSlugsAndLegacyIds`. Слаги генерируются только после слияния.

---

## Архитектура URL

```
/places                              → все места
/places/{category}                   → /places/abandoned
/places/{location}                   → /places/bashkortostan, /places/orenburg
/places/{location}/{category}        → /places/bashkortostan/cave
```

- **Локация всегда первой.** Обратный порядок (`/places/cave/bashkortostan`) — 301 на канонический.
- **Одна локация в пути**, самая конкретная; иерархия — хлебными крошками, не путём.
- **Одна категория в пути.** 2+ категории — только query-параметром (`/places/orenburg?category=abandoned,military`): `noindex, follow`, canonical на путь без категории. `GET /places` принимает `category` списком через запятую. Мультивыбора в UI нет.
- Метки, сортировка, пагинация, гео-фильтр — query-параметры поверх пути. Любой `?category=` на странице локации или `?tag=` — `noindex`.
- Уровни локации: страна, регион, район, населённый пункт. Районы — полноценный уровень (много мест вне городов).
- Один слаг на обе локали: `/places/orenburg` и `/en/places/orenburg`.

### Порог индексации

Индексируются только страницы с ≥ 5 мест — один порог для всех уровней, `Config\LocationSlugs::$indexThreshold` (на клиенте зеркало `LANDING_INDEX_THRESHOLD`). Сервер отдаёт поле `indexable` во всех ответах landing-API и в `GET /sitemap`. Ниже порога — `noindex, follow` и не в sitemap.

- Локация или пара: страница с 0 мест отдаёт 404; слитая/переименованная локация — 301.
- Категория с 0 мест — 200, `noindex`, пустое состояние «добавьте первое место» (`pages/places/landing/[...slug].tsx`): в категорию ведут фильтр и ссылки, 404 выглядел бы поломкой.

## Слаги локаций

- **Одно пространство имён** для всех уровней: таблица `location_slugs` (`slug → type, entity_id, is_primary`), уникальный `slug`. Зарезервированы ключи категорий, служебные слова (`Config\LocationSlugs::$reservedWords`) и строки, начинающиеся с 13 hex-символов (формат id места).
- **Генерация** (`App\Libraries\LocationSlugLibrary`): только из `title_ru` (`title_en` ненадёжен), фиксированная транслитерация — не менять после запуска; тип поселения срезается (`село Никольское` → `nikolskoe`, `$settlementTypeWords`), у районов остаётся (`sovetskiy-rayon`); нижний регистр, дефисы, до 80 символов по границе слова. Слаг выдаётся `locations:rebuild` для существующих и геокодером при создании новой локации. Пока слага нет, `slug` равен `null` и локация в путь не попадает.
- **Коллизии:** чистый слаг получает приоритетный уровень (страна > регион > район > город, `$levelPriority`), внутри уровня — локация с бо́льшим числом мест, затем меньший id. Остальные уточняются ближайшим родителем (`parizh-chelyabinskaya-oblast`, `sovetskiy-rayon-orenburgskaya-oblast`), не суффиксом `-2`; крайний случай — `-l{id}`. Зарезервированное слово тоже уточняется родителем.
- **Неизменяемость и история:** выданный слаг сам не меняется (ни при переименовании, ни при повторном геокодировании). Любая смена пишет старый слаг в `location_slug_history`, он отдаёт 301 на актуальный. Верхний регистр в пути — 301 на нижний.
- `location_legacy_ids` — временная таблица для 301 со старых `/places?region=2`; удалить через несколько месяцев после этапов 3–4.

## Морфология и шаблоны заголовков

Строки собирает Next.js из i18n; PHP отдаёт данные. Названия категорий — на клиенте (`public/locales/<lang>/common.json` → `categoryCatalogue.<name>`: `title` для чипов, `landing` — H1 страницы категории и пары, `content` — вводный текст). Title категории — шаблон `landing-title-category-seo`.

Падежных форм локаций (`name_genitive_ru`, `name_prepositional_ru`, через `morphos` с ручной правкой) **нет** — ни колонок, ни генерации. Поэтому заголовки локаций без склонения («Интересные места: Башкортостан»). Это открытая часть, см. ниже.

## Роутинг

- Плоские URL — rewrite в `client/proxy.ts` на одну страницу `pages/places/landing/[...slug].tsx`, только при включённом флаге этого типа. Снаружи URL остаётся плоским; одна страница — нет перемонтирования при смене фильтров. Прямой заход на внутренний маршрут закрыт.
- `/places/{id}/edit` не конфликтует: id распознаётся по формату.
- Резолв сегмента: категория → `GET /locations/resolve` (слаг → история с 301) → 404 (`client/utils/placesLandingResolve.ts`).
- UI фильтров не менялся; фильтр на `/places` собирает канонический путь (`buildPlacesHref`). Старые query-URL отдают 301 на новые при включённом флаге (`pages/places/index.tsx`), остальные параметры переносятся.

## Шаблон страницы

Один скелет: фильтры и список мест на одном месте, меняются заголовок и контекстные блоки.

| Блок | `/places/{category}` | `/places/{location}` | `/places/{location}/{category}` |
|---|---|---|---|
| H1 | «Заброшенные места» | «Интересные места: Башкортостан» | название категории + локация |
| Описание | `categoryCatalogue.<name>.content` | сводка по данным | сводка по данным |
| Карта | — | ✓ | ✓ |
| Чипы категорий со счётчиками | — | ✓ | ✓ другие категории здесь |
| Ссылки на локации | ✓ эта категория по регионам | ✓ дочерние районы и города | ✓ эта категория рядом |

Перелинковка — `components/shared/location-link-list` (`LocationLinkList`).

### Описание

У категории — её текст. У локации и пары — сводка из данных (`GET /locations/{type}/{id}/summary`): число мест, состав по категориям, дата последнего добавления.

### Карта

Компактное превью (~200px, `components/shared/landing-map-preview`), Leaflet грузится лениво при попадании в экран. Кнопка «Открыть на большой карте» → `/map` с этой локацией и `?category=`. На страницах категорий карты нет (места по всей стране).

### Хлебные крошки и JSON-LD

Иерархия как в URL: `Главная › Места › Башкортостан › Пещеры`. На карточке места адрес и категория ведут на посадочные (категория — на пару «самая конкретная локация + категория», когда включены комбинации). `BreadcrumbList` на листингах и карточках, `ItemList` на листингах.

## SEO-паттерны

| Паттерн | Правило |
|---|---|
| Canonical | Самоканонический путь без `sort`/`order`/гео; 2+ категорий → путь без категории |
| Пагинация | Каждая страница самоканоническая и индексируемая, title и H1 с суффиксом «— страница N», страница за пределами диапазона — 404, без `rel=prev/next` |
| Hreflang | `/en/places/orenburg` ↔ `/places/orenburg` |
| Sitemap | Только индексируемые страницы (порог ≥ 5 мест), по флагам: `GET /sitemap` → `client/pages/sitemap.tsx` |
| noindex, follow | Ниже порога; 2+ категорий; гео-фильтр; `?category=` на локации, `?tag=` |
| 404 / 301 | См. «Порог индексации» |

## Технические требования

**Эндпоинты** (`server/app/Controllers/Locations.php`, `Categories::locations`, подробно — `server/API.md`):

| Эндпоинт | Назначение |
|---|---|
| `GET /locations/resolve?slug=…` | slug → `{type, id, названия, slug, родители, indexable}` или `redirect` на новый слаг |
| `GET /locations/{type}/{id}/categories` | категории с числом мест (чипы) |
| `GET /locations/{type}/{id}/children` | дочерние районы и города |
| `GET /locations/{type}/{id}/summary` | данные для сводки |
| `GET /categories/{name}/locations` | топ локаций по категории |
| `GET /places` | `category` списком через запятую |

## Поэтапный запуск

**Не запускать всё одним днём.** Каждый этап переводит целый тип страниц сразу: страницы, 301 со старых адресов, ссылки на сайте и sitemap меняются в один деплой (флаг в `ui-deploy.yml`, вшивается при сборке). Между этапами 2–4 недели: смотреть в Вебмастере индексацию новых URL, 301, ошибки и трафик.

| Этап | Флаг | Что | Состояние |
|---|---|---|---|
| 0–1. Данные и инфраструктура | — | Геокодер, слияние дублей, слаги, landing-API | сделано |
| 2. Категории | `NEXT_PUBLIC_LANDING_CATEGORIES` | `/places/{category}`, 301 с `?category=` без локации, ссылки категорий, sitemap | включается в 1.14.x |
| 3. Локации | `NEXT_PUBLIC_LANDING_LOCATIONS` | `/places/{location}` всех уровней, 301 с `?country/region/district/locality=`, ссылки адреса на карточке, sitemap | выключено |
| 4. Комбинации | `NEXT_PUBLIC_LANDING_COMBINATIONS` (только вместе с этапом 3) | `/places/{location}/{category}`, 301 со старых комбинаций, ссылка категории с карточки на пару, sitemap | выключено |

До этапа 4 «локация + категория» — query-параметр на странице локации (`/places/bashkortostan?category=cave`), `noindex`, canonical на `/places/bashkortostan`.

Перед этапом 3: убедиться, что `locations:rebuild` прогнан на проде и у локаций есть слаги.
